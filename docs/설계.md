# MLNG MES 설계 — 공정별 모듈 + 공통 기반

## 1. 원칙
| 원칙 | 내용 |
|---|---|
| 모듈은 따로, 기반은 하나 | 공정 모듈은 자기 화면·표만 갖고, 기준 정보·LOT·이력·알림·검사는 공통 표를 쓴다 |
| 이어 붙이는 키 = LOT | 공정 모듈은 작업마다 `mlng_lots` 에 공정 LOT 하나를 남기고 `mlng_trace` 로 앞 LOT 과 잇는다 |
| 기존 시스템은 그대로 | MCT MES(`mes_`)·용접 웹(`weld_`)은 고치지 않는다. 공정 흐름에서 «별도 시스템» 으로 링크 |
| 같은 로그인 | MCT MES 와 같은 Supabase Auth · `mes_profiles` · `mes_role()` |
| 제품 데모 | 원본 행 대신 요약값, 고객사 식별 정보(품번·작업자·소재 LOT)는 데모 코드로 |

## 4. 열처리 모듈 (`supabase/heat_schema.sql`)
라인: 세정 → 소입로 4존 (860 °C, CP 0.45 %C) → 솔트조 2존 (332 °C) → 솔트 컨베이어 → 건조로 2존 (100 °C)

| 화면 | 내용 |
|---|---|
| 열처리 현황 | KPI(처리 수량·불량률·기준 초과·조건 이탈), 라인 상태(구역별 평균), 일별 불량률, 불량 유형, 최근 작업 |
| 작업 실적 | 작업(LOT) 목록·필터·검색 → 작업 상세(공정값 2분 그래프, 조건 요약, 검사 기록) |
| 공정 조건 | 설정값·허용 폭, 이탈 시간·이탈 작업, 불량률과 함께 움직인 조건 |
| 설비 상태 | 존별 히터 출력 추이, 초기 대비 변화 |

현장 알림 (config.js 에서 기준 조정)
- 불량률 관리 기준 초과 / 2배 초과 작업 — 기준 450 PPM (원 데이터의 안정·위험 구분선)
- 조건 이탈 — 한 작업에서 허용 범위 밖 시간이 5 % 이상
- 히터 출력 증가 — 초기 20작업 대비 최근 20작업 +5 %p 이상 (데모: 소입로 2존 +10.4 %p)

## 4-2. 프레스 모듈 (`supabase/press_schema.sql`)
순차 이송 금형, 취수 12 (데모 설정). 작업 1건 = 작업일.

| 화면 | 내용 |
|---|---|
| 프레스 현황 | KPI(타발·생산·불량률·설비 진단), 작업일별 불량률, 불량 유형(주름·터짐·버), 공정 능력(Cpk) |
| 타발 실적 | 작업일 목록 → 상세(20타발 평균 추이 + 허용 띠, 소재 LOT·다음 열처리 LOT) |
| 공정 조건 | 설정·허용·Cpk, 압력 2 설정 변경 이력 (데이터에서 계단 변화 감지: 274 → 268) |
| 설비 진단 | 진동·전류 1초 RMS, 정상 기준(상위 1%), 이상 구간 기록 |

현장 알림
- 불량률 기준(150 PPM) 초과 작업일
- 불량 증가 추세 — 최근 3작업일이 그 전의 2배 이상 (데모: 59 → 162 PPM, 2.8배)
- 허용 범위 밖 타발 1 % 이상인 작업일
- 진동 이상 — 정상 기준 대비 배수 (데모: 7.3배, 46초)

## 4-3. 정밀가공 검사 모듈 (`supabase/insp_schema.sql`)
부품 번호별 가공 신호 요약 + 합격 판정. 하루 검사분 = LOT 1개, 앞 LOT = 검사일 전 마지막 열처리 작업일.

| 화면 | 내용 |
|---|---|
| 검사 현황 | KPI(검사 부품·불합격·판정 확정 필요·사이클 타임), 시간대별 불합격률 p 관리도, 검사 LOT (앞 공정 링크) |
| 부품 이력 | 부품 목록·필터(확정 필요/불합격)·검색 → 부품 상세(기록별 신호, 합격 분포 위 위치) |
| 가공 신호 | 불합격 기록에서 달랐던 신호(효과 크기, 같은 번호 짝 차이), 분포 비교 |

데이터에서 찾은 현장 문제 → 알림
- 같은 부품 번호·같은 시각에 합격·불합격이 함께 기록된 부품 99개 (불합격 기록 99건 전부) → «판정 확정 필요»
- Z2축 전류·부하 8개 항목이 모든 부품에서 고정값(30.3) → 센서·수집 설정 확인
- 시간대별 불합격률이 p 관리도 상한을 넘으면 알림 (데모 데이터에서는 없음)

## 4-4. 점용접 모듈 (`supabase/weld_schema.sql`)
용접 품질 웹의 점용접 화면(공정 모니터·용접 로브·검사 우선순위·안정 공정조건)을 그대로 옮기고, 작업일 LOT(WD-)으로 프레스·열처리와 잇는다.
아크용접(Polito 데이터, CC BY-NC)은 상업 데모에서 뺐다. 검사 기록은 공용 검사 기록(대상 = 타점 번호)으로 남긴다.

## 4-5. 계획 모듈 (`supabase/plan_schema.sql`)
| 화면 | 내용 |
|---|---|
| 생산 계획 | 기어 2품목: 수주·생산·마감 재고 추이, 재고 일수, 내일 필요 생산 = 예상 수주(최근 7작업일 평균)×(1+안전재고 50%) − 마감 재고, «작업지시 만들기»(초안), 일별 계획 대비 실적(다음날 부족 여부) |
| 작업지시 | 모든 공정 작업지시 + 초안, 공정·상태 필터, 실적 LOT 연결 |

알림: 마감 재고 < 내일 예상 수주 → «추가 생산 필요»

## 4-5-2. MCT 가공 모듈
NASA Ames / UC Berkeley Milling Data Set — Matsuura MC-510V 수직형 머시닝센터, 공구 16개(가공 167회), 센서 6종(주축 전류 AC/DC, 진동 2, AE 2), 플랭크 마모 VB.
| 화면 | 내용 |
|---|---|
| MCT 현황 | 현재 공구 VB·남은 수명, 최근 가공·부품, 교체 기준 넘긴 가공(→ 검사 강화 부품 수), 현재 공구 마모 곡선, 공구별 마모 속도 |
| 공구 수명 | 공구별 조건·가공 횟수·최종 VB·마모 속도·교체 적정 여부 → 공구 상세(마모 곡선·센서 추이·가공 기록) |
| 가공 조건 | 재질×절삭깊이×이송별 마모 속도와 교체까지 시간, 마모와 함께 움직인 센서(주축 전류 DC +0.77), 데이터 점검 |
알림: 현재 공구 VB ≥ 0.5 mm → 공구 교체 / 최근 교체 기준 넘긴 가공 → 해당 부품 검사 강화 / 센서 값 비정상
공구 1개 = 하루 작업(열처리 마지막 16작업일), 가공 1회 = 부품 25개 (데모 설정). 미측정 VB 는 측정값 보간, 보간 불가 시 신호 추정(공구 단위 교차검증 오차 ±0.11 mm)

## 4-6. 라인 운영 (공정 통합 조정)
공정마다 데이터에서 «현재 속도»(최근 7일 작업일 평균 처리량), «관측 최대 능력»(가장 많이 처리한 날), 수율, 경로 비율(점용접 = 프레스 물량의 일부, MCT·검사 = 열처리 물량의 일부)을 계산한다.
- 공정별 속도(%)·계획 수량을 바꾸면 → 최종 가능 산출, 병목, 앞뒤 공정 수급 차이(재공 증감/일), 능력 사용률이 다시 계산됨
- 목표 산출 1개당 각 공정이 처리해야 하는 양 = 뒤 공정 필요량 ÷ 수율 (경로 비율 반영)
- «목표에 맞춤» / «능력 한계에 맞춤» / «현재로», 조정 제안의 «적용»
- 현재 재공을 넣으면 뒤 공정이 멈추는 시점(일) 계산
- 선택 공정의 앞뒤 공정·알림(예: 프레스 진동 이상 → 증속 전 점검 권장)

## 4-6-2. 구매·발주 (`supabase/buy_schema.sql`)
- `mlng_purchase_orders`: 발주 1건 = 거래처 1곳, 품목 `lines`(jsonb), 결재 `signs`(jsonb), 상태 pending → approved → received
- `mlng_audit`: 발주 등록 · 단계별 결재(서명자) · 결재 물림 · 발주서 출력 · 입고 처리
- 등록 품목 `web/js/catalog.js` 전체를 공구 주문 표에 올리고 추천은 표시만 한다 — 추천이 없는 품목도 골라서 발주 (MCT MES 와 같은 설계)
- 추천: MCT 인서트 = 최근 7일 공구 교체 × 날 수 × N주 − 재고 − 발주 중 / 그 외 = 품목의 `on` 화면을 가리키는 알림이 뜨고 발주 중이 아니면
- 결재가 끝나기 전에는 발주서를 출력할 수 없다. 출력본 기본값은 결재란 없는 거래처 발송본

## 4-6-3. 질의응답 (`supabase/functions/mlng-ask`)
- Edge Function 이 Claude API 를 중계 — 키는 함수 비밀값. 시스템 지시·도구 정의는 함수에서만 정한다
- 도구 9종(overview · alerts · process_detail · lot_trace · line_status · mach_tools · plan_status · purchase_orders · buy_recommendations)은 브라우저가 실행 → 화면 값과 답 값이 같고 원본 데이터 전체를 보내지 않는다
- 함수가 없거나 실패하면 규칙 기반 엔진이 답한다

## 4-7. 데모 공장 구성 (데이터 상태 화면에 표시)
- 프레스(2020년)·열처리(2022년)는 서로 다른 공개 데이터 → 프레스 18작업일을 열처리 마지막 18작업일의 전날로 옮겨 날짜를 맞춤
- 소재 LOT → 프레스 LOT → 열처리 LOT → 검사 LOT 을 날짜로 연결, 프레스 기간 밖 열처리는 소재 → 열처리
- 검사(2022-08-23~25)는 37일 앞당겨 열처리 마지막 날(07-19)에 끝나게 맞춤. 검사 셀은 가공 사양 부품만 거치므로 수량이 작음 → 공장 생산 수량은 열처리 완료 기준(OUTPUT_PROC)
- 압력 단위·허용 폭은 원 데이터에 없어 데모 값 (고객사 공차로 교체)
- 점용접 9작업일(학습 8일 + 타점별 자료가 있는 예측일)을 프레스 마지막 9작업일에 맞춤 (예측일 = 07-18), 소재 → 프레스 → 점용접 → 열처리
- 생산 계획(기어 2품목)은 21일 옮겨 07-19 에 끝나게 맞춤
- 프레스 불량 기록 중 1일(원 데이터 05-19)은 타발값이 없어 제외
