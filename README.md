## 구매·발주 / 질의응답
- **공구 주문**: 등록 품목(`web/js/catalog.js`, 공정별 30종) 전체를 표로 보여 주고, 공정 알림·사용량에서 «추천» 을 표시한다. 추천이 없는 품목도 체크해서 함께 발주 (MCT MES 공구 주문과 같은 방식). MCT 공구는 MCT MES 공구 목록에서 이 제품 가공(정면 밀링·구멍·탭·모따기·윤곽)에 해당하는 것만 가져왔다
- **발주 · 결재**: 담당 → 검토 → 승인 3단계 전자결재, 결재 물리기, 입고 처리. 모든 동작은 활동 기록(`mlng_audit`)에 남는다
- **공구 발주서**: MCT MES 발주서 양식(결재란 도장 · 발주번호/요청부서/요청자 · 품목 표 · 발주 기준). 결재가 끝난 건만 출력, 「미입고 발주서 출력」으로 여러 건을 한 번에. 기본은 결재란을 뺀 발송본, 「결재란 포함」을 켜면 사내 보관본
- **질의응답**: Supabase Edge Function `mlng-ask` 가 Claude API 를 중계 (키는 함수 비밀값에만). Claude 가 도구로 자료를 요청하면 브라우저가 지금 열린 데이터에서 찾아 돌려준다. 함수가 없으면 규칙 기반으로 답한다

### Claude 질의 켜기 (PowerShell, 한 줄씩)
```
npm install -g supabase
supabase login
supabase link --project-ref <MLNG 프로젝트 ref>
supabase secrets set ANTHROPIC_API_KEY=sk-ant-...
supabase functions deploy mlng-ask --no-verify-jwt
```
- `config.js` 에 SUPABASE_URL 이 있으면 주소는 자동 (`/functions/v1/mlng-ask`). 따로 두려면 `ASK_URL`
- 로그인 없는 공개 사이트이므로 **Anthropic 콘솔에서 월 사용 한도(Spend limit)를 꼭 건다**. 함수에는 IP 당 호출 제한·요청/답 길이 상한이 들어 있다
- 접속 주소만 허용하려면 `supabase secrets set ASK_ALLOW_ORIGIN=https://dksgusrl04-gif.github.io`

## 5.0 정돈 — 주문부터 출하까지 한눈에

현업 피드백(「너무 정신없다 · 대시보드에서 한눈에 안 보인다」)을 반영해 화면 구조를 MES 기본 흐름으로 다시 짰다. 기능은 하나도 지우지 않았다.

- **메뉴 47개 → 7개**: 대시보드 · 주문 · 자재·구매 · 생산 계획 · 공정 실적 · 품질 · 출하. 세부 화면은 메뉴 안의 탭(공정은 공정 탭 + 현황/실적/조건/설비 작은 탭). 분석 · AI · 데이터 신뢰 · 시스템 화면은 접힌 «더보기».
- **대시보드 = 주문 → 자재 → 생산 → 품질 → 출하 한 줄**: 단계마다 신호등 · 숫자 하나 · 확인할 문제 개수. 단계를 누르면 아래 «주문 진행» 과 «지금 처리할 문제» 가 그 단계로 좁혀진다.
- **주문 현황(신규)**: 주문마다 납기(D-day), 주문 → 출하 진척 막대, 상태(정상 · 납기 위험 · 납기 지연 · 품질 확인), 확인할 점. 주문을 열면 그 주문의 실제 열처리 LOT · 품질 판정 · 출하 상태 · 걸린 품질 문제가 보인다 (`web/js/mod_flow.js`, 데모 주문 장부는 최근 LOT 을 납품 단위로 묶어 만든다).
- **2.0~4.0 기능은 제자리로**: 사건실 → 품질 › 품질 문제, 출하 게이트 → 출하 › 출하 판정, What-if → 생산 계획 › 계획 시뮬레이션, 스마트 발주 → 주문 › 고객 계약·납품, 교대 인수인계 → 대시보드 탭.
- **조용한 화면**: 긴 부제는 ⓘ 툴팁으로, 오른쪽 요약 패널은 상단 한 줄 KPI로, 긴 안내문은 두 줄로 접힘(눌러 펼침), 머리줄 단추 정리(서버 미연결 단추 숨김 · 테마는 아이콘).
- **5.1 현황판 대시보드 · 정렬 원칙**: 대시보드를 현장 현황판 형태로 — KPI 한 줄(오늘 생산 · 진행 주문 · 납기 준수 · 불량 · 출하 대기 · 품질 문제) → **주문 진행 현황판**(행 = 주문, 열 = 주문·자재·생산·품질·출하, 칸마다 진척/상태 색, 단계 머리를 누르면 그 단계로 좁혀짐) → 일별 생산 실적 | 공정·설비 상태 → 처리할 문제 표. 모든 화면에서 나란한 카드는 위·높이를 맞추고, 표는 고정 열 폭 · 숫자 오른쪽 정렬 · 같은 행 높이, 요약 줄은 같은 상자 · 같은 칸 폭.
- **5.2 현업 용어 통일**: 화면 전체를 제조 현장 · MES 표준 용어로 교체 — 주문 → 수주, 알림 → 알람, 사건/사건실 → 품질 이슈(8D: 접수 · 봉쇄 조치 · 원인 분석 · 시정 조치 · 재발 방지 · 종결), 지금 처리할 문제 → 이상 발생 · 조치 현황(등급 · 구분 · 이상 내용 · 예상 손실 · 조치), 걸린 돈 → 예상 손실(발생 손실 · 잠재 손실 · 보류 재고 · 에너지 손실), 출하 게이트 → 출하 승인, 스마트 발주 → 전자 발주, 자동 검수 → 자동 수입검사, 계약 조항 → 품질 협정 기준, 원인 후보 → 추정 원인(연관성 높음 · 보통 · 낮음), 품질 증명서 → 품질 성적서, 라인 균형 → 라인 밸런스, 넘김/받음 → 인계/인수, 되감기 → 과거 시점 조회, 돈으로 보는 공장 → 품질 비용(COPQ). 이전 원장 기록(«사건 감지 — …»)도 그대로 복원된다.
- **5.3 가정값 관리 · 전체 공정 화면**: 더보기 › 시스템 › 가정값 관리 — 단가 · 클레임 비용 · 위험 비율 · 전기요금 · 배출계수 · 재고 · 관리 기준 26개를 한 표에서 보고 고친다(저장하면 모든 화면 재계산, 변경은 신뢰 원장 기록, 실측 확인 체크). 확인 안 된 값을 쓰는 수치(손실 금액 · 출하 판정 · 기회 손실 · 탄소 · 발주 추천)에는 「가정 포함」 표시 (`web/js/mod_assume.js`). 공정 실적 › 전체 공정 — 소재 → 프레스 → 점용접 → 열처리 → MCT → 검사 → 출하 흐름도(공정 사이 재공 증감), 공정별 실적 표, LOT 흐름(최근 열처리 LOT 의 앞뒤 공정 LOT · 출하 상태). 품질 비용 화면은 설명문을 걷어내고 표 중심으로 정리.
- **5.4 글자 최소화**: 화면의 설명문(.note)은 모두 카드 제목의 ⓘ 안으로 옮기고, 화면에는 숫자 · 표 · 결과 메시지만 남긴다(소제목 바로 아래 본문은 유지). 라인 밸런스: 노드에서 공정 태그 · 미니 그래프 · 긴 라벨 제거(필요 · 현재 · 수율 · 가동률), 조정 제안은 한 줄(상세는 마우스), 요약 줄 라벨 단축.
- **5.5 현업 기본 기능** (OEE 대시보드 · 작업자 단말 · 안돈 · 일보의 업계 표준 배치를 참고)
  - 데모 데이터 정비: 공개 데이터 날짜를 오늘 기준으로 이동(LOT · 작업지시 번호 속 날짜 포함), 프레스 취수 24로 물량 역전 해소, 머리줄 「데모 데이터」 표시
  - 알람 A/B/C 등급(`config.js ALARM_GRADE`, ISA-18.2 분포 참고): A 즉시 조치 · B 당일 조치 · C 관찰. 신호등은 등급을 따른다. 알람 이력에 등급별 집계 · 필터
  - 설비 · OEE (`mod_oee.js`): 설비별 OEE = 가동률 × 성능 × 양품률, 손실 워터폴, 비가동 사유 파레토(누적 80%), 일별 추이(목표 85%), 설비 가동 타임라인. 비가동 관리: 자동 감지 정지 · 미분류 사유 입력, MTBF · MTTR
  - 실적 입력 POP (`mod_pop.js`): 태블릿 터치 — 설비 · 작업자 선택, 작업 대기열, 시작/비가동/완료, 양품 · 불량 키패드, 불량 사유 필수, 비가동 사유 → OEE · 원장 반영
  - 생산 일보 (`mod_report.js`): 결재란 · 공정별 계획 대비 실적 · 불량 · 비가동 · 수주 · 특이사항, 엑셀(5개 시트) · 인쇄(A4 가로)
  - 엑셀: 외부 라이브러리 없는 .xlsx 생성기(`xlsx.js`), 표가 있는 모든 카드에 「엑셀」 단추
  - 현장 모니터(안돈): 머리줄 단추 → 전체 화면 · 설비별 상태 · 현재 시각까지 목표 대비 실적 · OEE · A/B 알람, 30초 갱신
- **5.6 품질 데이터 분석** (`mod_spc.js`, 품질 메뉴 + 더보기 › 분석)
  - SPC 관리도: 열처리 불량률 Laney p′(LOT 수량이 커서 생기는 과산포 보정, σz 표시 · 일반 p 관리도와 이상 점 수 비교), 프레스 압력 X̄-R(n=5, 설정값 변경 보정), 용접 전류 · 가압력 X̄-R(n=10), 열처리 온도 I-MR. 앞 60% 로 한계 → 뒤 40% 감시, Western Electric 5규칙, 이상 판정 내역
  - 공정능력: 히스토그램 + LSL/USL + 정규 곡선(군내 · 전체), Cp · Cpk · Pp · Ppk + 95% 신뢰구간(Bissell · 카이제곱, 자기상관 유효 표본), 비정규는 백분위 Ppk(ISO 22514-2) 로 판정
  - 불량 층별 분석(4M): 불량 유형 · 설비별 파레토, 교대 · 작업자 · 히터 출력 · 조건 이탈 · 원자재 LOT · 장입량 · 요일 층별 PPM(Garwood 95% 구간) · 순열 검정 p · BH q
  - 예측 모델 검증: 학습에 안 쓴 데이터로 예측 대 실제 — 열처리(이탈도 · MAE · 90% 상한 적중 · Brier · AUC), 공구 수명(80% 구간), VB(MAE · RMSE · 컨포멀), 수요(1일 앞 롤링 MAPE). 히터 변화점 · 검사 점검 · 라인 시뮬레이션은 «미검증» 표시 (히터 신뢰도 하향, 수요 신뢰도는 백테스트 적중률로)
  - 품질 이슈 상세 «분석 보고서»: 문제 정의 → 관리도 → 층별 → 원인 검정 → 결론 → 조치 · 효과 검증 (8D 보고서 D4 에도 반영)
- 시험: e2e 70개 (5.6 분석 16개 포함) · e2e 54개 (현황판 5단계 열 · 모든 행 5칸 · 나란한 카드 위·높이 일치 포함) · 이전: e2e 32개 (메뉴 7개 · 모든 화면이 메뉴 어딘가에 있음 · 5단계 · 단계 필터 · 주문 ↔ LOT 연결 · 주문 서랍 · 공정 탭 추가).

## 4.0 — 판단하고, 스스로 의심하고, 증명하는 MES
숫자 하나 대신 확률로 말하고, 상관 대신 원인을 확인하고, 모든 판단에 데이터 · 모델 · 코드 해시를 서명한다. 메뉴 그룹 「증명하는 AI (4.0)」 + 기존 화면에 녹아 있음.
1. **확률로 판단** — 출하 게이트가 LOT 마다 «참 불량률이 계약 기준을 넘을 확률» 을 낸다 (조건 기반 포아송 회귀 + 과산포 → 사후 감마). 기대 손실(확률 × 클레임 비용) > 보류 비용이면 보류 권고. 같은 PPM 이라도 조건이 나쁘면 확률이 높다
2. **스스로 의심하는 AI** — 「모델 상태」: 모델마다 검증 구간 적중률(컨포멀 · 홀드아웃 · 공구 하나씩 빼기)과 입력 분포 변화(PSI)로 신뢰도. 근거 모델이 «신뢰» 가 아니면 에이전트가 자동 실행을 내려놓고 승인을 기다림 (예: Z2축 센서 고착 → 검사 강화 지시 자동 실행 중단)
3. **원인을 실험** — 사건실 원인 후보마다 순열 검정 p · 부트스트랩 90% 구간 · BH 다중 비교 보정 q. 불량률 후보는 «A/B 를 몇 작업씩 번갈아 운전하면 가릴 수 있나» 를 계산해 확인 실험 계획으로 제안
4. **변화의 순간** — 히터 출력 · 프레스 불량률 · 공구 마모 속도의 변화점(평균 변화 + 순열 p, CUSUM). 「처음 징후」 가 규칙 알림보다 며칠 먼저 알 수 있었는지(조기 경보 시간)를 보여 주고 되감기로 그날로 이동
5. **처음 보는 공구도 첫날부터** — 공구 마모 VB = a·t^b, 같은 재질 다른 공구로 만든 계층 베이즈 사전 + 이 공구 측정으로 축소 추정 → 잔여 수명 80% 구간. 측정이 쌓일수록 구간이 좁아지는 모습과 검증(공구 하나씩 빼고 처음 3회만으로) 적중률
6. **판단 증명** — 보류 · 출하 · 사건 조치 · 에이전트 실행 · 계획 적용마다 데이터 해시 · 모델 버전 · 코드 빌드 해시 · 결과 해시를 원장에. 「재현」 = 저장한 입력으로 지금 코드가 같은 결과를 내는지 다시 계산
- 그 밖에: What-if 에 몬테카를로(하루 실적 흔들림 → P10~P90 · 목표 달성 확률), 수요 예측 Holt + 95% 서비스 수준 안전재고, 질의응답 도구 `model_status` · `tool_life` · `claim_probability` · `decision_proof`

  - 조치 일괄 승인: 남은 조치를 한 번에 실행 → 단계 진행 → 8D 보고서
  - 처음 징후: 공장 되감기로 같은 종류 알림이 며칠 전부터 이어졌는지(조기 경보 시간) 측정
- **돈으로 보는 공장**: 홈의 사건을 금액 순으로 정렬하고 「조치하면 막는 돈」 표시. 모든 알림을 실손 · 위험 · 묶임 · 낭비(원/일)로 바꾸고 계산식을 공개. 30일 품질 손실(COPQ)과 매출 대비 비율, 기회 손실
- **출하 게이트**: 아직 납품하지 않은 LOT 을 고객 계약 조항으로 «출하 전에» 미리 판정 → 보류 권고 · 보류 · 출하(→ 고객 자동 검수). 다음 LOT 기준 초과 확률 예보. 보류 규칙은 회사가 정함
- **What-if 샌드박스**: 프레스 속도 · 용접기 대수 · 열처리 가동 · 공구 교체 기준 VB · 히터 정비 · 열처리 설정값 이탈 비율을 바꾸면 산출 · 병목 · 판단 이익(클레임 기대 비용 포함) · 탄소 · 계약 충족이 함께 바뀜. 「최적 찾기」(계약을 새로 어기지 않고 품질 기준 VB 0.5 이하인 조합 중 이익 최대) · 시나리오 비교 · 계획으로 적용
- **공장 되감기**: 데이터를 그날 밤까지로 잘라 «그때 MES 가 무엇을 알았나» 를 다시 계산 (공정 요약 · 라인 · 재공 · 계약·납품 · 알림 · 그날 일어난 일 · 재생)
- **교대 인수인계**: 이번 교대에 바뀐 것만 브리핑 + 다음 교대가 꼭 할 일 자동 추출 → 넘김 서명 · 받음 서명(모두 확인해야) → 원장

## 2.0 — 신뢰로 연결되는 MES
회사 사이(완성차 A · 1차 협력사 B · 우리 C · 강판 공급사 D)를 «서명된 데이터»로 잇는다. 메뉴 그룹 「연결 · 신뢰 (2.0)」 와 「AI 에이전트」.
- **데이터 공유 계약**: 누가 · 무엇을(범위 7종) · 언제까지 · 재공유 여부를 양쪽 회사 키로 서명. 계약이 없으면 조회가 막히고, 허용·거부 모두 기록
- **신뢰 원장**: 모든 계약·발행·검수·조치가 해시 사슬 + 회사 서명으로 쌓인다. 「전체 검증」·「위변조 시험」으로 바로 확인
- **보안 구조**: 회사별 ECDSA P-256 키(WebCrypto), 공개키 지문, 검증 방식 설명
- **LOT 디지털 여권**: 소재(D사 서명 성적서) → 프레스 → 점용접 → 열처리 → MCT → 검사를 해시 사슬로 묶고 우리 서명. QR 링크(`#verify=`)로 누구나 진본 확인
- **공정 능력 증명서**: 원본 대신 «기준 충족» 만 서명해서 고객사에 발급 (근거 데이터는 해시만)
- **탄소 발자국**: LOT 별 소재·공정 에너지 기반 g/개 (계수는 `config.js PCF`, 예시값)
- **스마트 발주**: 고객 발주에 품질·탄소 조항을 넣으면 납품 때 여권으로 자동 검수 → 합격은 정산 승인, 미달은 근거 붙은 클레임 자동 생성
- **공급망 동기 계획**: 완성차 계획 변경 → B·우리·D 필요량·병목 재계산 → 「변경 전파」로 라인 목표·작업지시 초안·협력사 회신
- **함께 배우는 AI**: 4개 공장이 원본 대신 요약 통계(XᵀX·Xᵀy)만 모아 공구 마모 모델 학습 (NASA 데이터 시뮬레이션)
- **AI 에이전트**: 알림·계획·클레임에서 조치안을 만들고, 정책(자동/승인/제안)에 따라 실행 — 실행은 모두 원장에
- 질의응답에 `trust_network` 도구 추가 → 함수 다시 배포: `supabase functions deploy mlng-ask --no-verify-jwt`

### 2.0 실시간 저장과 한계
- 실시간 모드에서 서버에 남기는 것은 **원장(`mlng_ledger`)과 공개키(`mlng_keys`)** 뿐 — anon 은 추가만 가능(수정·삭제 불가). `supabase/trust_schema.sql` (new_project_setup.sql 에 포함)
- 계약·발주·여권 등 시나리오 자체는 화면 안 메모리(데모). 데모 시드 기록은 서버 원장에 넣지 않는다
- 데모 키는 브라우저에서 만든다. 운영에서는 회사별 키를 서버(HSM/KMS)에 두고 서명 함수로만 서명해야 한다
- 연합 학습은 시뮬레이션, 탄소 계수는 예시값, 전자 계약의 법적 효력은 별도 검토가 필요하다

## 자체 서버 (server/)
- Supabase 대신 **내 VM 에서 직접**: Nginx(화면 · HTTPS) + FastAPI(같은 REST 문법 · Claude 중계) + PostgreSQL(같은 스키마 · RLS) + 매일 백업 — `docker compose up -d --build` 한 줄
- 화면 코드는 그대로: Nginx 가 `js/runtime.js` 로 «이 서버 주소 · 공개 키» 를 내려 주면 `config.js` 값을 덮어쓴다 (GitHub Pages 에서는 빈 파일)
- push → 시험(화면 · API 단위 · 컨테이너 smoke) → 통과하면 SSH 로 VM 배포 (`.github/workflows/deploy.yml`, 켜는 법은 server/README.md)
- 자세한 순서 · 보안 설계 · 운영 명령: [server/README.md](server/README.md)

## 배포·Supabase
- GitHub Pages: 저장소 Settings → Pages → Branch `main` / `(root)`. 루트 `index.html` 이 `web/` 으로 넘겨 준다
- Supabase: **MLNG 전용 새 프로젝트** (MCT MES 프로젝트와 섞지 않는다)
  1. SQL Editor 에 `supabase/new_project_setup.sql` 전체를 붙여 넣고 Run (표 31개 + 로그인 없는 anon 권한)
  2. Project Settings → API 의 URL·anon 키를 `web/js/config.js` 에 넣고 push
- 표가 비어 있는 동안은 데모 스냅샷을 그대로 보여 준다. «데이터 상태» 화면에서 연결 상태를 확인할 수 있다
- 로그인이 없어서 anon 키로 읽기 + 검사 기록·작업지시 초안·발주·활동 기록 «추가», 발주 결재·입고 «수정» 만 열려 있다 (삭제 불가)

## 새 공정 모듈 붙이기
1. `web/js/mod_<공정>.js` — `MLNG.mod({ id, proc, group, menu, views, alerts, summary, drawers })`
2. `supabase/<공정>_schema.sql` — 공정 전용 표만. LOT 은 `mlng_lots`, 이력은 `mlng_trace`, 알림·검사는 공용 표
3. `build_demo.py` 의 설비 `status` 를 `live` 로 → 공장 현황·LOT 이력에 자동으로 나타난다

## 지켜야 할 것
- MCT MES 프로젝트의 Supabase·저장소는 건드리지 않는다 (MLNG 는 별도 프로젝트·저장소)
